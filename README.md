# EcoPath.AI

**Sustainability Decision, Comparison, Computer Vision Eco-Scoring and Action Platform**

> *Understand your impact. Find your next best action. Measure what changes.*

EcoPath.AI is a student-led sustainability innovation project that connects observation, understanding, comparison, decision-making, action, and verification in one integrated workflow.

## Quick Start

### Prerequisites
- **Node.js** 18+ (tested with 22)
- **Python** 3.11+ (tested with 3.13)
- **pip** (Python package manager)

### 1. Clone and Setup

```bash
# Install frontend dependencies
cd frontend
npm install

# Install backend dependencies
cd ../backend
pip install -r requirements.txt
```

### Optional: Enable Eco-Scorer

Eco-Scorer requires local YOLOX-Tiny ONNX weights. From the project root, run:

```bash
python scripts/download_cv_model.py
```

The model is not committed to the repository. Without the weights and inference dependencies, the rest of EcoPath.AI works normally, Eco-Scorer navigation is hidden, and the image-analysis API does not return simulated results.

### 2. Initialize Database

The backend creates database tables when it starts and does not seed demo workspaces or resource
records. Create an account or sign in with your email and password, then create a personal or business
workspace. The first account created on an existing installation adopts its existing live workspaces;
later accounts cannot see or access those workspaces. Workspaces and application records are scoped
to the signed-in account. You can switch, create, or delete your workspaces from the sidebar. Deleting a workspace permanently
deletes its associated resource records, actions, comparisons, organization data, and Eco-Scorer
assessments after confirmation. Existing database contents are not otherwise deleted. Legacy demo
workspaces and their records are preserved in the database but are hidden from the workspace UI and
rejected by live workspace APIs. Logging out revokes the current persistent session without deleting
data; signing in again restores the account's saved workspaces and records. Sessions expire after 30
days. Set `SESSION_COOKIE_SECURE=true` when serving the application over HTTPS. Dashboard greetings
follow India time without displaying a timezone label. Currency and date display are configured for
India (INR and `en-IN`).

Demo fixtures are not part of the live startup path. `scripts/seed_demo_data.py` is only for a
disposable presentation database and requires the explicit `ECOTWIN_ALLOW_DEMO_SEED=1` opt-in.

### 3. Start the Application

**Terminal 1 — Backend API:**
```bash
cd backend
python -m uvicorn app.main:app --host 0.0.0.0 --port 8000 --reload
```

**Terminal 2 — Frontend:**
```bash
cd frontend
npm run dev
```

Open **http://localhost:5173** in your browser.

### 4. API Documentation

With the backend running, visit **http://localhost:8000/api/docs** for interactive Swagger documentation.

## Architecture

```
OBSERVE → UNDERSTAND → IDENTIFY → COMPARE → DECIDE → ACT → MEASURE → IMPROVE
```

| Layer | Technology | Purpose |
|-------|-----------|---------|
| Frontend | React 19, TypeScript, Vite | User interface and data visualization |
| Backend API | FastAPI, Pydantic | RESTful API with validation |
| Database | SQLAlchemy + SQLite/PostgreSQL | Persistent data storage |
| Calculations | Python modules | Documented, deterministic formulas |
| Recommendation Engine | Rule-based Python | Transparent, traceable recommendations |
| Computer Vision | Optional YOLOX-Tiny (ONNX) | Local COCO object detection; no environmental score from appearance |
| Internal guidance | Structured JSON/DB | Curated content used to support deterministic recommendations |

### No Generative AI

This application does **not** use OpenAI, Gemini, Claude, or any LLM/chatbot API. All recommendations are generated by deterministic rules with documented formulas. Computer vision uses a genuine object detection model (YOLOX-Tiny, Apache 2.0 license).

## Live Data and Regional Settings

The normal application startup does not seed demo workspaces or resource, action, or comparison
records. Users create workspaces and enter their own measurements and INR costs. Calculations that
need missing usage, tariff, or product-specific inputs remain incomplete instead of substituting
sample values. Environmental estimates are withheld when a suitable verified India-specific factor
is unavailable.

## Environment Variables

Copy `.env.example` and adjust:

| Variable | Default | Description |
|----------|---------|-------------|
| `DATABASE_URL` | `sqlite:///data/ecotwin.db` | Database connection |
| `CORS_ORIGINS` | Local development origins | Allowed frontend origins; the deployed Vercel frontend origin is also allowed |
| `SESSION_COOKIE_SECURE` | `false` | Force secure cookies; HTTPS requests and HTTPS reverse-proxy requests automatically receive cross-site secure cookies |
| `DEBUG` | `true` | Enable SQL logging |
| `CV_MODEL_PATH` | `computer_vision/models/yolox_tiny.onnx` | CV model location |
| `CV_CONFIDENCE_THRESHOLD` | `0.35` | Object-detection threshold (not sustainability confidence) |

Eco-Scorer's model, input validation, confidence interpretation, evidence-only review formula, knowledge-base mappings, and limitations are documented in [docs/COMPUTER_VISION_METHOD.md](docs/COMPUTER_VISION_METHOD.md).
